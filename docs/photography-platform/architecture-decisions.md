# Architecture decisions

Interval 0, 2026-10-22. Each decision is labelled with its status:

- **Validated:** demonstrated in this repository.
- **Observed:** read from live hosts or upstream repositories.
- **Design:** reasoned, not yet built.
- **Assumption:** needs confirming by the owner or an account check.

Background is in [repository-audit.md](repository-audit.md),
[raw-feasibility.md](raw-feasibility.md) and
[editor-hdr-architecture.md](editor-hdr-architecture.md).

## Target shape

```text
quanghuynh.com (Vercel, static)                      admin.quanghuynh.com (Cloudflare)
  /photography/          gallery (unchanged)           Cloudflare Access ─► admin Worker ─► R2 (private)
  /photography/editor    local-first editor              (owner only)       │  catalog.json + history
  /admin/photography ──► redirect ────────────────────►                      │  originals/<sha256>
                                                                             │  previews/<sha256>.webp
GitHub repo ◄── publish PR (catalog snapshot) ◄─────────────────────────────┘
   └─ Actions: prepare-photography --only (originals read from R2) ─► tests, build ─► owner merges ─► deploy
```

The public gallery stays a build-time static page, and the editor needs no
server. Only the owner's CMS uses new infrastructure.

## 1. CMS authentication and authorization

**Decision:** put **Cloudflare Access** in front of a dedicated admin Worker
on `admin.quanghuynh.com`. The Worker verifies the `Cf-Access-Jwt-Assertion`
header on every request:

- the signature against the team's JWKS,
- `aud`, `iss` and `exp`,
- the email equals the owner's.

The `workers.dev` route is disabled. `quanghuynh.com/admin/photography`
becomes a `noindex` redirect to it; the GitHub Pages mirror gets no admin.

| Option | Tradeoff |
| --- | --- |
| **Cloudflare Access + JWT check in the Worker** | No custom auth code. MFA and revocation come from the identity provider; the free plan covers up to 50 users (*documented, not checked*). The zone is already on Cloudflare (**observed**). |
| Owner bearer credential (256-bit secret, SHA-256 digest in env), as in the archive's sharing design | Simple, but a long-lived secret lives in the browser: no MFA, phishable, and exposed to any XSS |
| GitHub OAuth via Auth.js on Vercel Functions | Adds the site's first server runtime and session handling to maintain |
| Vercel Deployment Protection | Protects whole deployments, not a path; it is not application auth |

The UI must be served from the protected host itself. A
`quanghuynh.com → admin.quanghuynh.com` API call would depend on the Access
cookie and on login redirects across hosts, which fetch cannot complete.

**Assumptions:**
- The owner can use the Cloudflare account that holds the zone, and enable
  Access and R2 there.
- A subdomain is acceptable for the CMS UI.

## 2. CMS persistence

**Decision:** keep the working catalog as **one JSON document in a private R2
bucket**.

- Writes are conditional (`If-Match` on the ETag), and each write keeps the
  previous version under `catalog/history/`.
- The published state is a snapshot of that document, committed to this
  repository.
- Records keep today's model: array order is curated order, a `featured`
  ordinal, a category, tags, and `status: draft | published`.
- Collections are named, ordered lists of IDs; today's categories become
  collections.

| Option | Tradeoff |
| --- | --- |
| **JSON document in R2** | One binding, no migrations, atomic whole-catalog updates, and matches the current array-order model. Fine for one owner and thousands of records. |
| Cloudflare D1 (SQLite) | Real queries and transactions, but a schema and migrations for data that fits in about 100 KB |
| Neon Postgres (as in the archive design) | Another vendor and network hop. Worth converging on only if the archive's sharing service is deployed. |
| Git only (repository as database) | Rejected: the repository is public, so drafts and private originals would leak |
| Workers KV | Rejected: eventually consistent, so the last write can be lost |

Revisit if the CMS grows to several editors or to archive scale (10,000+
records with search).

## 3. Image asset storage

- **Private:** one R2 bucket with no `r2.dev` endpoint and no custom domain.
  - Originals (JPEG, PNG, WebP, TIFF, ARW, DNG) are keyed by SHA-256, so
    re-uploads deduplicate.
  - Uploads under 100 MB go through the Worker (the Workers request body
    limit on Free and Pro, *documented limit, not checked in Interval 0*), or use
    a presigned S3 `PUT`.
  - CMS thumbnails are made in the owner's browser (canvas, WebP, about
    600 px) and stored under `previews/`.
- **Public:** published derivatives stay in this repository exactly as today.
  - They are generated by the existing `scripts/prepare-photography.mjs`
    (sharp, mozjpeg, metadata stripped, GPS never written) in a GitHub
    Actions publish workflow.
  - That workflow reads originals with a bucket-scoped **read-only** R2
    token.
  - This keeps the deterministic, tested pipeline and leaves the gallery
    unchanged.
- **RAW originals** are stored, but sharp cannot decode them. A RAW-only
  upload therefore needs either an editor export or, later, a libraw-wasm
  render inside the Action (the Node path is **validated** in the PoC).
- **Rejected:**
  - Runtime-served public images from R2: they would bypass the build's
    hashed URLs, sitemap and JSON-LD.
  - Cloudflare Images: a paid transform service that duplicates sharp.

## 4. Publishing, states and cache invalidation

**Decision:** publishing **opens a pull request**. The Worker then:

1. Writes the published catalog snapshot to a `cms/publish-<timestamp>`
   branch, using a GitHub App or a fine-grained token limited to this
   repository with `contents` and `pull_requests` write.
2. A workflow runs `prepare:photography --only <new ids>`, deletes the
   derivatives of withdrawn photographs (the glob ships every file), and
   commits to the branch.
3. CI runs the tests and the build.
4. The owner merges, which deploys to Vercel and Pages.

Rollback is a revert. This keeps the rules in `AGENTS.md` (no direct commits
to `main`; merging deploys only with the owner's approval) and every existing
CI gate.

- **States:**
  - Draft: R2 only.
  - Published: in the repository.
  - Featured: an ordinal in the published record.
  - Withdrawn: removed from the snapshot and its derivatives deleted.
- **Cache:**
  - Derivative URLs are content-hashed by Vite, so new images never collide
    with cached ones.
  - HTML is `max-age=0, must-revalidate` on Vercel and `max-age=600` on Pages
    (**observed**), so Pages can lag up to 10 minutes.
- **Latency:** minutes per publish (*assumption*). Auto-merge after green
  checks is possible if the owner prefers (open question).

**Migration of existing photographs:**
- Interval 1 converts `photographs.overrides.mjs` and `photographs.generated.json`
  into one validated, machine-writable catalog in the repository, with
  identical rendered output.
- The CMS later seeds its R2 catalog from that file.
- Existing derivatives are kept, and originals are not needed for the
  migration.
- Build-only library paths stay out of anything shipped.

## 5. RAW decoder

**Decision:** use **libraw-wasm 1.6.0** (LibRaw 0.22.1), pinned exactly and
used only behind our own adapter, `decodeRaw(bytes, options) → { linear
Uint16 RGB, metadata }`, in a dedicated worker.

- Upgrades are gated on fixture output checksums.
- If upstream stalls or a fix is needed, build LibRaw 0.22.x with Emscripten
  ourselves.
- dcraw.js was rejected on evidence: the decode crashed, it has no colour
  tables for these bodies, and it is GPL.
- Status: **validated** for A6400 compressed ARW in Chromium and Node.
  It is also **validated** for A7 III uncompressed 14-bit and 12-bit ARW.
  A7 III compressed ARW and DNG are **unvalidated**, because the archive
  holds neither.
- Comparison: [raw-feasibility.md](raw-feasibility.md#candidates-compared).

## 6. Rendering and adjustment pipeline

**Decision:** a fixed-order, per-pixel pipeline.

- Linear Rec.2020 float working data, then a source-dependent base rendering,
  then display-referred curve and LUT.
- Implemented as WebGL2 shaders for preview and export, plus a JS float32
  CPU reference that defines correctness.
- Parity tests compare GPU to CPU (at most 1/255 in 8-bit output) and proxy
  to full resolution (mean ΔE2000 below 1).
- Alternatives:
  - WebGPU: later.
  - CPU only: too slow for interactive use.
  - CSS or Canvas filters: rejected.
- Status: **design**.

## 7. LUT processing

**Decision:**
- Our own `.cube` parser (1D and 3D, `DOMAIN_*`, Resolve's input-range
  keywords), with strict count and finiteness validation.
- Tetrahedral interpolation in both the CPU reference and the shader, from a
  `NEAREST`-sampled 3D texture so the two match.
- Applied to display-referred values after the base rendering, matching the
  owner's LUT headers (Rec.709 in and out).
- No dependency is needed. Status: **design**; the header format is
  **observed** on the owner's files.

## 8. HDR processing

**Decision:** a **browser-only** merge of three RAW brackets:

1. Validate the EXIF and geometry.
2. Decode identically, with shared white-balance multipliers.
3. Align by MTB translation.
4. Merge radiance with exposure time, ISO and aperture, using weights that
   exclude noise and clipping.
5. Deghost against the middle frame.
6. Tone-map in the editor's filmic base rendering.

Not offered:
- JPEG brackets (they need response recovery) are deferred.
- Averaging or overlaying frames is not a merge.

Server-assisted merging was rejected for v1: Workers are capped at 128 MB of
memory (documented limit, not checked in Interval 0), so it would need containers, and it would mean uploading 75–150 MB of private
originals per merge. Status: **design**. Memory and time are *estimates*
built from the measured per-frame figures.

## 9. Workers and memory

**Decision:**
- One reused decode worker, terminated on cancellation.
- One image worker for codecs, LUT parsing and HDR.
- Transferable buffers only; monotonic job ids so the latest preview wins.
- A device-memory budget with a half-size RAW fallback.
- At most one full-resolution working image in memory.

Status: partly **validated**:
- worker reuse stays flat at 673 MB,
- half-size decoding needs 316 MB against 559 MB at full size,
- direct embind use leaks about 256 MB per instance without `delete()`.

## 10. Session persistence and privacy

**Decision:** the editor makes no uploads and no third-party requests,
enforced by a CSP.

- Edits and presets go in IndexedDB.
- Source files are retained only on opt-in, in the Origin Private File
  System, with a clear-session control.
- Exports strip metadata by default.
- Storage failures (private windows) degrade to "no restore" and never block
  editing.
- In the CMS, originals stay private in R2. Public metadata keeps today's
  rules: no GPS, factual captions, no identifiable people.

Status: **design**.

## 11. Test strategy

- **Unit tests (Vitest, offline):**
  - catalog schema and validator,
  - CPU-reference adjustment math (neutral equals identity),
  - `.cube` parsing,
  - HDR weighting and merge, and MTB on synthetic shifted images.
- **Fixture tests (opt-in):** `RAW_FIXTURE`-style environment variables, as in
  the PoC.
  - Private RAWs never enter the public repository.
  - Golden checksums of decoded output are committed per pinned decoder
    version.
  - A synthetic, generated DNG could give CI a real decode test without a
    private file (Interval 3 investigation).
- **Browser tests:**
  - The existing CDP-to-headless-Chromium pattern, for GPU/CPU parity, memory
    and worker behaviour.
  - Firefox and WebKit coverage would need Playwright as a dev dependency
    (owner approval).
- **CMS Worker tests:** `@cloudflare/vitest-pool-workers` (already used by
  `spotify-portfolio-api`) with a simulated R2. Requests with a missing,
  expired, wrong-`aud` or wrong-email JWT must be rejected.
- **Regression:** the existing 268 tests plus a check that
  `/photography/index.html`, the sitemap and the curated order are unchanged
  by the migration.

## 12. Hosting compatibility

- **Editor:** static on both Vercel and Pages.
  - Its route is added through `ROUTES`, `seo-plugin` and a `vercel.json`
    rewrite, like `/about`.
  - The editor, decoder and wasm load only in its lazy chunk, never on the
    gallery.
  - COOP/COEP are **not required** (validated in Chromium only).
  - Adopting a future threaded build would need COOP/COEP:
    - Vercel can scope these headers to the editor.
    - Pages cannot, so the mirror would stay single-threaded.
- **Base path:** Pages serves under `/portfolio/`, so all worker and wasm URLs
  must come from `import.meta.url` or `BASE_URL`.
  - libraw-wasm creates its worker with
    `new URL('./worker.js', import.meta.url)`.
  - Vite's dependency pre-bundling can break that pattern; it may need
    `optimizeDeps.exclude` (*unverified*, Interval 3).
- **CMS:** Cloudflare (Access, Worker, R2) plus GitHub Actions. Vercel's role
  is unchanged.
